PROJECT RAPTOR — ASTRA MASTER MISSION
Native Rust Linux 3D Scanning, Reconstruction, and Editing

OBJECTIVE
Build, test, optimize, document, and publish a fully native open-source Rust replacement for CrealityScan, initially for the Creality CR-Scan Raptor. The final product must independently acquire real sensor data, reconstruct dimensionally accurate 3D geometry, provide full point-cloud and mesh editing, and export usable models without Windows, Wine, CrealityScan, or proprietary Creality runtime dependencies. This is a working software deliverable, not a GUI mockup or research report.

EXISTING RESOURCES
The Raptor is physically connected and already communicates through Linux. CrealityScan is installed and runs under Wine. Verify exactly which acquisition and scanning functions work; preserve the current functioning environment. Use CrealityScan as a behavioral reference, the physical scanner for hardware validation, and established open-source libraries as algorithmic and numerical references. Distinguish verified findings from hypotheses.

RUST POLICY
Rust is the primary and final target language for device communication, acquisition, calibration, image processing, depth reconstruction, registration, point clouds, mesh algorithms, editing, measurement, GPU orchestration, rendering, GUI, storage, and tests. Evaluate rusb, nalgebra, glam, rayon, wgpu, serde, tracing, criterion, Slint, and egui. Prefer proven Rust crates where adequate. Study OpenCV, Open3D, PCL, CloudCompare, MeshLab, Eigen, and Ceres as references. Port or independently implement necessary algorithms in Rust while complying with licenses and attribution. Temporary C/C++ dependencies may accelerate early milestones but maintain a roadmap to eliminate mandatory C++ reconstruction runtime dependencies before stable release. Do not delay working acquisition merely to rewrite mature libraries. Favor safe idiomatic Rust and isolate/test unavoidable unsafe code.

ARCHITECTURE
Create a modular Rust workspace separating device interface, acquisition, recording/replay, calibration, image processing, depth, point-cloud representation, registration/tracking, point-cloud editing, mesh reconstruction, mesh editing, measurements, GPU rendering/compute, GUI, project persistence/import/export, and automated tests. Keep scanner hardware, reconstruction, and visualization decoupled. Use bounded queues, reusable buffers, documented coordinate systems, and versioned formats. Design for future scanners.

RECORD AND REPLAY

Support integrity checks, controlled corrupted-file handling, repeatable offline replay, algorithm comparisons, and regression benchmarks without rescanning. Minimize memory copying. Preserve redistributable test datasets where lawful.

RECONSTRUCTION ENGINE
Implement image decoding, undistortion, denoising, exposure normalization, feature and laser-line detection, structured-light decoding where required, synchronization, calibration, coordinate transforms, triangulation, depth estimation, point-cloud generation, normals, confidence filtering, and invalid-point rejection. Implement correspondences, point-to-point/point-to-plane ICP, robust outlier rejection, manual and multi-frame registration, global alignment, pose optimization, tracking-loss detection/recovery, fusion, spatial indexing, voxel methods, surface reconstruction, mesh generation, simplification, and supported color mapping. Compare outputs against reference algorithms and physical ground truth.

LIVE SCANNING
Provide live camera and point-cloud previews; start/pause/resume/stop; scan-mode selection; continuous registration; tracking status/recovery; multi-session acquisition; progress; save/load; and performance diagnostics. Decouple acquisition, reconstruction, and rendering so slow stages do not freeze the UI or silently discard data. Define queue backpressure and frame-drop reporting.

POINT-CLOUD EDITING
Provide rectangle, freehand lasso, polygon, brush, 3D box, plane trimming, clipping planes, visible-only/through selection, delete/keep/invert, hide/isolate, previews, undo/redo. Implement statistical/radius outlier filtering, duplicate/isolated point removal, voxel downsampling, density filtering, smoothing, background/table removal, disconnected-component removal, and normal correction. Preserve originals, support non-destructive edits, expose parameters, and protect small legitimate details.

MESH EDITING
Implement surface reconstruction, smoothing, decimation, trimming, plane cuts, hole detection/selective filling, normal recalculation, non-manifold detection, mesh repair, disconnected component removal, merging/splitting, watertightness checks, and quality analysis. Provide previews and reversible operations; never silently fill intentional openings or distort precision features.

MEASUREMENT AND REVERSE ENGINEERING

Investigate future primitive recognition, mechanical feature extraction, reference-model comparison, CAD-oriented fitting, and parametric reconstruction. Benchmark CPU versus GPU and retain portable CPU fallbacks. Never accept speedups that violate geometric accuracy.

MEASURABLE ACCEPTANCE GATES
The following are PROVISIONAL engineering thresholds, not manufacturer claims. Benchmark CrealityScan per mode and calibrated physical ground truth first; document hardware, datasets, test methods, uncertainty, and any justified revisions. Track PASS/FAIL/BLOCKED with evidence, never assume PASS.
- Device: 20/20 discovery; >=19/20 initialization; normal reconnection <=10 seconds; >=10 minutes continuous valid acquisition; <0.1% corrupted frames (report drops separately); zero qualification crashes.
- Recording: 100% saved-frame integrity; required metadata preserved; 100 successful replay runs; controlled truncated/corrupted-file errors.
- Geometry: dimensional error <=0.20 mm or <=0.20%, whichever permits larger absolute error; plane-fit RMS <=0.15 mm; repeated measurement standard deviation <=0.10 mm; qualified registration RMS <=0.25 mm; scale deviation <=0.20%; zero NaN/infinite exported coordinates. Adjust only with documented reference and uncertainty evidence.
- Live: >=90% of valid incoming frame rate processed; >=20 FPS preview on designated hardware; p95 preview latency <=150 ms; >=30-minute continuous scan; tracking failures detected; zero qualification crashes.
- Editing: >=99.9% selection accuracy on labeled synthetic data with boundary tolerances; exact selected-index delete/keep; 100% geometry restoration by undo/redo; <=500 ms trim of one million points on designated hardware; 100 edit/undo cycles without crashes.
- Registration: synthetic translation error <=0.10 mm; rotation error <=0.10 degrees; >=95% convergence on qualified data; bad alignments flagged.
- Mesh: >=95% reconstruction success on qualified datasets; zero invalid vertices; <=0.20 mm surface deviation on designated references; export/import precision documented; non-manifold conditions reported.
- Performance: no unbounded memory growth in a 60-minute workload; >=90% of CrealityScan comparable throughput and >=90% of its geometric quality against independent ground truth where meaningful; accuracy never sacrificed.
- Rust: all independently developed production reconstruction modules in Rust by stable release; no mandatory C++ reconstruction runtime dependencies; zero release-CI compiler warnings; all mandatory tests pass; unsafe code reviewed; dependency licenses verified.

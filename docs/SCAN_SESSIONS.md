# Native cloud sessions and offline sequence replay

`scancraft_geometry::session::ScanSession` couples the bounded tracker and voxel
fusion map in one world frame. It has Ready → Running, Running ↔ Paused, and
terminal Stopped states. Start/resume/pause in the wrong state return errors;
paused/stopped sessions consume no input frames. Stop preserves cloud/history
for inspection. Create a new session object to establish another world; there
is no hidden tracker reset that could mix coordinate systems in an old map.

Each process call supplies a full cloud (up to 100,000 points), a monotonically
increasing frame ID and 3..512 explicit unique tracking indices. The complete
cloud is fused; tracking uses the indexed subset. The first accepted frame
anchors world identity. Only the small tracker is copied for tentative updates,
not the potentially large fusion map. Tracker reference, accepted pose and
history publish only after fusion successfully commits. A failed fusion can be
retried with the same frame ID: it did not advance tracking or consume history.
Rejected alignments instead publish a Lost/history record without integrating;
later accepted frames recover against the retained reference.

History is bounded to 1..100,000 attempts and is never silently evicted. A full
history fails before tracking/fusion mutation. Invalid input/cancellation before
commit also leaves state unchanged. Once fusion commits, tracker/history commit
without another cancellation boundary. This guarantee excludes allocator aborts
and process crashes. The controller exposes separate last accepted/integrated
IDs and read-only history; it does not expose independent resettable internals.
All prior tracking/fusion limitations still apply, including symmetry/local
minima and unqualified spatial averaging.

## Offline command

```
scancraft-cli fuse-sequence SETTINGS_JSON NEW_OUTPUT_DIRECTORY
```

The shared workflow reads a schema-1 request with `session_id`, `source`,
`tracking`, `voxel_mm`, `maximum_voxels` and `frames`. Each frame specifies `id`,
`path` and `tracking_indices`. Relative frame paths resolve against the settings
file directory. Source is explicitly `synthetic_fixture` or `unverified_imports`;
neither can assert physical qualification. Tracking fields are documented in
`TRACKING.md`; a complete runnable example is generated by:

```
cargo run --release -p scancraft-cli --example synthetic_sequence_dataset -- NEW_SYNTHETIC_INPUTS
./target/release/scancraft-cli fuse-sequence NEW_SYNTHETIC_INPUTS/sequence.json NEW_SYNTHETIC_RESULT
```

The generator refuses an existing directory. It creates four six-point frames:
anchor, small translation, deliberate loss, recovery. Expected output is three
integrated frames, one rejection and six fused points. All data is synthetic.

Settings are a bounded regular JSON file (4 MiB); frames are bounded regular
ASCII PLY files (64 MiB each) with explicit recognized units, converted to mm
by the existing parser. Unknown units are rejected. Requests contain 1..1000
frames; session/cloud/tracking/voxel caps apply too. Only one input file/cloud
is processed at a time, plus bounded state/history. Processing errors abort
publication rather than silently skipping frames. Rejected local alignments
are valid recorded outcomes and processing continues for possible recovery.

Output is a new atomically published no-overwrite directory containing:

- `report.json`: stopped-session state, declared source, input lengths/CRCs,
  tracking/fusion configuration, per-frame poses, selected tracking indices,
  acceptance/rejection reasons, coverage and residuals.
- `points.ply`: derived fused cloud with mm units and available attributes.
- `project.orproj`: existing editable project format for that derived cloud.
- `manifest.json`: summary and artifact lengths/CRCs.

Every report keeps physical accuracy and synchronization unverified. A standalone
project contains derived geometry/edit history, not resumable fusion weights,
trajectory or originals: preserve the bundle and input data for lineage. Partial
output after a write error is retained under an explicitly reported staging
path. No existing target is overwritten. This command is offline; it does not
control the scanner, prove calibration, connect to the camera stream or add a
new GUI scanning mode. The exported project uses the existing native file-open
workflow.

Five new regressions cover session lifecycle/loss/recovery, transactional rollback
of tracker/fusion/history, cancellation and samples, plus CLI sequence replay,
pose composition, integrity manifests, exact project/PLY equality, no overwrite,
and invalid/corrupt/unsupported input failures. All 178 workspace tests, Clippy,
formatting and release workspace build pass. The release CLI also ran the
reproducible four-frame dataset (`evidence/session-sequence-run.json`); its
report is retained privately with inputs. This is synthetic workflow validation,
not real scanner or live throughput qualification.

## Native workbench integration

Open **Point clouds → Track and fuse cloud sequence**, enter the sequence JSON
and a new result folder, then select **Track, fuse and open**. The offline job
runs on the geometry worker with progress/cancellation; current unsaved edits
use the existing save/discard/continue guard before replacement. On success the
fused cloud opens in the editor, with integrated/rejected frame totals in the
status message. Per-frame pose/loss diagnostics remain in `report.json`.

A fresh workbench can also start this job without camera acquisition:

```
./target/release/scancraft --fuse-sequence INPUTS/sequence.json NEW_RESULT_FOLDER
```

The shared workflow now separates immutable preparation from durable output
publication. The GUI builds its proposed editor and viewport preview before
publishing the bundle, then replaces the document only after publication
succeeds. Invalid input, cancellation before commit, or an existing output
retains the old editor/history/selection. A directory-sync failure after rename
explicitly reports the published output path; it cannot undo disk publication.

A new GUI-worker regression checks saved/displayed geometry equality and
original-document preservation for cancellation, missing inputs and existing
targets. Existing unsaved-document and startup-parser tests now include sequence
jobs. All 179 workspace tests, Clippy, formatting and release build pass.

Actual software-rendered startup on a separate authenticated X display shows
six fused points and the 3-integrated/1-rejected status. Original dark synthetic
colors were hard to distinguish from the viewport, so the reproducible demo
now uses bright cyan attributes; raw source geometry and production rendering
are unchanged. The inspected render uses this bright fixture. No scanner
handles were opened and the user's desktop was not accessed. Its report,
PLY, project and manifest are byte-identical to a separate CLI run on the same
inputs (`evidence/gui-sequence-render-summary.json`). This verifies startup
processing/rendering and output parity; full interactive workflow, live camera
connection, physical accuracy and scanning throughput remain unqualified.
